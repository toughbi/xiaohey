# xiaohey 方案：agent.md 的八个问题，落到哪些机制上

这份文档回答两件事：`agent.md` 里每个问题在这个应用里怎么解，以及为什么这样解。每条都指向代码位置，也写清楚没解决的部分——方案的可信度取决于它承认哪里还漏。

总的原则只有一条：**不信任模型的自述**。目标、状态、验收、进度都必须落在磁盘上、能被重新读出来验证。模型只负责判断和写代码，不负责记账。

---

## 1. 多会话并发修改同一批文件

**问题**：多个会话同时改同一个文件；如果加锁，持锁的 agent 崩了怎么办。

**方案：按路径的租约（lease）+ 指纹，而不是按会话的全局锁。**

- 分区是首选，但单工作区产品里分区要靠 git worktree，代价是每次开会话都要一份检出。这里选择「分区能分则分（不同会话通常动不同文件），分不了就按路径串行」。
- 读工具（`read_file`/`grep_text`/`glob_files`/`list_dir`）完全不加锁，只读不冲突。
- 写工具（`write_file`/`edit_file`）以**目标文件的绝对路径**为键抢租约；`run_shell` 以 `exec:<tool>` 为键，所有命令串行——因为无法从命令文本判断它到底碰了哪些文件。
- 租约带 TTL（默认 90s）和**取得时的文件指纹**（sha1 前 16 位）。持有者崩了，租约到期自动可被接管，不会把工作区永久锁死。
- 接管时必做一次对账：当前指纹 ≠ 租约里的指纹，说明死掉的会话在持有期间已经改过文件，于是先按地面真相重读再写；指纹没变，重做是安全的。接管会在时间线里留一条通知，写明是谁、多久、有没有变过。

代码：`src/main/runtime/locks.ts`（`LockTable.acquire` 的 `takeover`）、`src/main/runtime/agent.ts`（`invoke` 里加锁、写意图、写提交、打快照）。

**没解决的**：租约表是 `leases.json`，两个进程（比如另开一个 CLI）同时写这个文件没有跨进程文件锁，理论上会互相覆盖。真要跨进程，得换成 SQLite 或命名管道的单写者；桌面单实例下这不是问题。另外这里没有实现「冲突后 LLM 语义仲裁」——同路径冲突被串行化之后，仲裁反而成了不必要的一层。

## 2. 多轮对话的指代消解

**问题**：实体（「客户」）、时间（「周三」「晚上」）、事件（「到了之后」）三类指代。

**方案：按类型分开处理，能用确定性代码的绝不交给模型。**

- **实体**：记忆里 `entity.*` 槽位就是这个工作区的实体表；命中文本就把 canonical 值放进本轮上下文，同一实体有多个候选时把歧义列表交给模型去问，而不是让它挑一个。代码：`resolve.ts` 的 `resolveEntities`。
- **时间**：确定性解析器把「下周三晚上 8 点」「明天下午」「3 天后」「11 月 18 日」归一成带时区的绝对时间窗（`fromIso`/`toIso`）。没有钟点的说法（如「周五」）标 `low` 置信度，并在时间线里出一条警告，让用户有机会纠正。代码：`parseRelativeTime`，时区取系统时区。
- **事件**：最容易被忽略的一类。锚点不是某句话，而是上一轮产生的事件对象，所以每条消息里的事件词（到达/会议/发布）配上一个钟点时间，就被**物化**成 `{id,label,atIso,timezone}` 存进 `resolution.events`；下一轮「到了以后」能直接对上时间戳。代码：`extractEvents`。

**没解决的**：事件锚点只覆盖「事件词 + 同句钟点」的形态；跨轮事件需要上一轮先说过钟点。实体表目前只来自记忆，没有接通讯录/CRM 之类的外部源。

## 3. 长任务跑偏

**问题**：目标、状态、验收标准、范围边界在长链路里逐轮衰减。

**方案：四样东西各自有对应的硬机制。**

| 会丢的东西 | 机制 | 位置 |
|---|---|---|
| 目标、验收 | 第一轮就把它们抽成**任务契约**（目标/验收/非目标/禁止），每 4 步把**原始需求原文**整段重新注入，而不是读摘要 | `contract.ts` `buildContract` / `MILESTONE_EVERY`；`agent.ts` 里程碑分支 |
| 状态 | 计划（`todo_write`）、记忆、检查点、日志全部落盘；每轮重新从磁盘读，不从聊天记录里回忆 | `store.ts` + `agent.ts` 的提示组装 |
| 验收 | 只认地面真相：命令退出码、文件是否存在、日志里有没有已提交步骤；**计划声称完成但没有写操作**会被对账点出来 | `audit.ts` `audits()`、`agent.ts` `verification()` |
| 范围 | 契约里的禁止项在写之前做路径/命令匹配，命中直接拒绝；破坏性命令必须二次确认 | `contract.ts` `checkDrift` |

另外两个边界：单轮最多 20 步、10 分钟（`MAX_STEPS`、`MAX_TURN_MS`），每一步结束后自动打检查点，所以「一步」天然是可回退、可验收的粒度。

**没解决的**：契约抽取是启发式的（按「验收/非目标/禁止」这类线索词切句），用户没说清验收时会给一个泛化默认值。这仍然是提示层约束，不是无法绕过的硬门；真正的硬门只有「损坏性命令」和「契约禁止路径」这两条。

## 4. 长任务断点续传

**问题**：崩在「写之后、确认之前」时，重启无法区分「没做」和「做了」。

**方案：L1 自报 + L2 对账，不做 L3。**

- L1：计划写在 `todo_write` 里，是给人看的进度，**不作为依据**。
- L2：每个写操作先写 `intent(step, idempotencyKey, before 指纹)`，执行，再写 `committed(after 指纹)`。崩溃后凡是停在 intent 的条目一律先对账：指纹等于 after → 已落地；等于 before → 没落地；都不是 → 无法判定，交给人和模型看，**任何情况都不自动重试**。代码：`journal.ts` 的 `reconcile`，`agent.ts` 开头的对账段。
- 每个检查点里存了完整会话状态（items、plan、memory、contract、resolution、折叠摘要），所以恢复不需要重放对话，也不需要「重算」。
- L3（Temporal/DBOS 式事件历史回放）没有做：接入成本高，而且这个应用的副作用大头是文件写入，已经有快照 + 日志覆盖。

**没解决的**：外部副作用（装依赖、跑迁移、调外部 API）仍然不可回滚，只在日志里留痕。这类操作的重试安全完全依赖幂等键，而不是回放。

## 5. 记忆冲突

**问题**：「住上海」→「回北京了」是更新；「别加注释」对「注释要写全」是冲突；全局「不加注释」对某仓库「必须写注释」是范围差异；而「住上海」和「不喜欢上海」根本不是冲突。

**方案：先分类，再决定动作。**

| 分类 | 判定 | 动作 |
|---|---|---|
| `supersede` | 同槽位、同 scope、值变了且极性相同 | 旧记录标 `superseded`，新记录生效 |
| `contradict` | 同槽位、同 scope、极性相反（否定词启发式） | **两条都保留**并标 `disputed`，提示里写「先问再使用」 |
| `scope_diff` | 同槽位、不同 scope | 两条都生效，各管一段 |
| `distinct` | 槽位不同，或值相同 | 原样保留 |

代码：`memory.ts` 的 `classify` / `applyClaim`；渲染进提示时 disputed 会带 `[DISPUTED — ask before using]`。

**取舍**：极性判定是启发式（中英文否定词），会误判。但两个方向的代价不对称——误判成 `disputed` 只是多问一句，误判成 `supersede` 会静默丢掉用户的一条要求，所以宁可多问。

## 6. 检查点回退

**问题**：回退要同时覆盖文件增删改、对话状态和不可回滚的副作用。

**方案：每步一棵影子树 + 一份完整状态，回退是「整棵替换」而不是「套 diff」。**

1. 模拟 git 提交：`snapshots/<thread>/step-004/tree/` 是**完整文件树**（跳过 `.git`、`node_modules`、`dist`），`meta.json` 存每个文件的哈希，`state.json` 存该步结束时的 items/plan/memory/contract/resolution/折叠摘要。
2. 回退时先校验哈希；任一文件被改过就拒绝回退，而不是恢复出一棵「半对」的树。
3. 用快照树覆盖工作区，**并删掉快照不认识的文件**——只 apply diff 会漏掉这一步新建的文件，这是最常见的回退 bug。
4. `state.items` 整份替换，不是「截断尾部」：中途可能发生过上下文折叠，截断会把折叠后的边界搞乱。
5. 回退后注入一条事实性通知：回到哪一步、撤销了哪些文件、别再走一遍。

代码：`checkpoint.ts`（`capture`/`verify`/`revert`）、`agent.ts` 的 `revert`。

**没解决的**：快照是整树拷贝，大仓库会明显变慢；副作用（装依赖、迁移）不可回滚，只能靠日志和通知。

## 7. 工具参数错误

**问题**：JSON 坏掉、schema 不匹配、语义错，三层失败需要不同处理。

**方案：三层分开，重试只给「模型能自己修」的那层。**

| 层 | 处理 | 预算 |
|---|---|---|
| L1 参数到不了 | 先做确定性修复：去 code fence、修引号、去尾逗号、补未闭合括号；仍失败才让模型重发 | 不需要模型介入 |
| L2 schema 不过 | 回灌**新信息**：错在哪个字段、期望什么、合法 schema 片段、一个正例 | 2 次，按调用计；耗尽就降级/问用户 |
| L3 语义错 | 领域错误 + 可执行提示（「先 list_dir 确认路径」）；**读可重试，写不自动重试** | 无 |
| transient | 超时 / 429 / 5xx：指数退避 | 3 次 |

代码：`toolerrors.ts`（`parseArguments`/`repairJson`/`schemaFailure`/`domainFailure`/`withBackoff`、`RETRY_BUDGET`）、`agent.ts` 的 `executeTool`。

**没解决的**：预算按 `callId` 记，模型换一个新的 callId 就重置了。要更严格得按「工具 + 参数指纹」记账，代价是同一处小错反复出现时会被永久挡住。

## 8. 调错工具

**问题**：该调不调、调错工具、幻觉工具、多步只做一步。

**方案：先收窄选择空间，再加后置校验。**

- 工具只有 **9 个**（上限 10–15 之内）。语义相近的能力合并成一个工具 + 参数，而不是并列两个让模型二选一。
- 每个工具的 description 写成路由依据：`Use when … Do NOT use when … (use X instead)`。`grep_text` 与 `glob_files` 的边界就是靠这句话分开的。
- 幻觉工具名不喂全部 schema，只回**合法工具名单 + 一行描述**（`agent.ts` 的 `executeTool` 分支）。
- 后置校验：`edit_file` 找不到片段 → 领域错误并要求重新读文件；`run_shell` 退出码非 0 → 不重试而是要求先改；计划为空 → 拒绝。
- 证据约束：回答里提到的文件名如果没有任何 `read_file`/`grep_text`/`glob_files` 结果覆盖，时间线里出审计通知（`context.ts` `auditClaims`），把「凭记忆答」变成可见的警报。

**没解决的**：没有做动态工具集（按阶段只暴露读写工具）。它和 prompt 缓存天然冲突，这个应用的流程又不够长，收益不抵损失。

## 批准方式：三档，而不是一个"是否确认"开关

输入框左下角的下拉不是装饰，它决定 `run_shell` 到底停不停：

| 档位 | 决策 | 实现 |
|---|---|---|
| 每次询问 `ask` | 一律停 | `autoDecision('ask', …)` 返回 `ask: true`，走原有的审批卡（允许一次 / 本会话允许 / 拒绝） |
| 自动审批 `auto` | 只对"看起来危险"的命令停 | `policy.ts` 里一张确定性规则表：递归删除、`del /s`、格式化、`git push --force` / `reset --hard` / `clean -f`、`drop table`、关机/杀进程、`curl … | bash`、全局安装、发布包、改注册表、改用户权限、提权、写入其他盘 |
| 完全访问 `full` | 不停 | 直接放行，审批卡不出现 |

三点约束：

1. **规则是代码，不是模型判断。** 同一批规则既用于 `auto` 的拦截，也用于契约禁止项之外的破坏性命令识别；`tests/selftest.ts` 有 9 条命令的正反例（`npm run build` 放行、`rm -rf` 拦截等）。
2. **放行不等于失控。** 即便是 `full`，意图日志、锁、检查点、契约拦截都照旧——批准方式只影响"要不要问人"，不影响可回滚性与可审计性。
3. **选择持久化在 `settings.json` 的 `approval` 字段**，但设置页仍然只有模型配置；切换入口就在输入框，符合"改这件事的时候离它最近"的原则。

**没做的**：没有像 Qoder 那样把"修改 Workspace 外文件"和"访问网络"单独建模成可授权的资源——本应用的写工具被 `resolveInside` 限制在工作区内，网络只能经命令访问，所以这两条被折进了命令规则（"写入其他盘"、"下载后直接执行"）。

## 工具清单

| 工具 | 风险 | 何时用 | 何时不用 |
|---|---|---|---|
| `list_dir` | 读 | 看一个目录有什么 | 已知道路径；按内容找用 `grep_text`，按名字找用 `glob_files` |
| `read_file` | 读 | 读一个已知文件的当前内容 | 找东西在哪用 `grep_text` |
| `glob_files` | 读 | 按文件名/扩展名找路径 | 找内容用 `grep_text` |
| `grep_text` | 读 | 按内容定位符号、配置、文案 | 已知文件用 `read_file` |
| `write_file` | 写 | 文件还不存在，或整份替换 | 只改一部分用 `edit_file` |
| `edit_file` | 写 | 精确替换一处片段 | 整份替换用 `write_file` |
| `run_shell` | 执行 | 构建、测试、类型检查 | 能用读工具回答的不要跑命令 |
| `todo_write` | 状态 | 多步任务开始或完成一步 | 单步修改 |
| `memory_write` | 记忆 | 稳定的偏好、约束、环境事实 | 一次性的本轮指令 |

## 参考 Codex 的部分

主进程充当 app server、渲染进程只是它的一个客户端，这是 Codex 的结构（[OpenAI: Unlocking the Codex harness](https://openai.com/index/unlocking-the-codex-harness/)）。照搬的：

- **thread → turn → item** 对象，item 的 `started → delta → completed` 生命周期，UI 只在 completed 时以最终内容替换（[app-server README](https://github.com/openai/codex/blob/08ba14b03d0b3ce3cfdf8c88c0469b9b1924953d/codex-rs/app-server/README.md)、[协议笔记](https://github.com/slopus/happy/blob/a6b1140317d3278d9838935583dd7f479f22515e/docs/competition/codex/message-protocol.md)）。
- **审批是服务端请求**：本轮挂起等一个决定，拒绝就是拒绝，不重试。
- **上下文折叠**替换模型可见历史、保留最近一段、摘要加前缀，并把它记成一条可展开的 item（[compact.rs](https://github.com/openai/codex/blob/08ba14b03d0b3ce3cfdf8c88c0469b9b1924953d/codex-rs/core/src/compact.rs)）。
- **会话落盘可恢复**：这里是每会话一个 JSON 文件，没有做 rollout JSONL + SQLite 双存储。
- **桌面外壳**：Electron 主进程持有 runtime，IPC 收窄；不照搬 Claude Desktop 的侧车 CLI 与版本握手（[Claude 桌面拆解](https://github.com/OpenAgentsInc/openagents/blob/8f84d05896ef14edee491621bf977ee5315cc8ed/docs/teardowns/2026-07-10-claude-desktop-app-teardown.md)）。

没照搬的：WebSocket/stdio 传输与握手、JSON-RPC 的 method 命名空间、MCP、动态工具集、子代理图、PTY 后台终端、SQLite 索引。这些在 Codex 的规模下必要，在这里只是成本。

## 界面：按本机 Qoder 的层结构复刻

界面改了三轮。第一版是暖灰纸感三栏，问题在**分区**：三列各有一块底色、三条满高的 1px 边线、每张卡片再套一层边框，读起来像被切成几块板。第二版压成一块画布 + 细线。第三版启动本机的 Qoder CN，截下窗口重新量了一遍结构与取色，按它的**三层结构**重做。

**层结构**（这是之前没做对的地方）：

1. 最底层是整窗画布 `#f6f6f6`，一直铺到窗口四边。窗口用 `titleBarStyle: hidden` + `titleBarOverlay`，原生最小化/最大化/关闭按钮直接画在画布上；顶部 52px 是可拖动标题条，放侧栏开关、品牌名、工作区名。
2. 画布之上浮着**一块白色圆角工作区**：1px `#e6e6e6` 边框、12px 圆角、四周 4px 边距（上下 2px）。侧栏不在工作区里，而是坐在画布上——这就是"画布 → 工作区"的从属关系。
3. 工作区内部才分左右两栏（会话流、文档区），中间一条细线；元信息不单独占一个底栏，而是**贴在输入框下侧**一行——轮次、步数、累计 token、上下文占用环，没有分隔线。

**取色**（从运行中的窗口采样，不是从截图猜）：画布 `#f6f6f6`、工作区 `#ffffff`、边框 `#e6e6e6`、选中行 `#e9e9e9`、悬停 `#ececec`；正文 `#1e1f1e`、次级 `#5f625f`、说明 `#949894`；强调色是**偏灰的鼠尾草绿** `#4b6f5a`（发送键、模式图标、进度），浅底提示 `#eef2ee`；改动 `+` `#2e7d4f` / `−` `#c0453a`。上一版用的是亮绿 `#1b9b3c` + 纯白画布，这就是"渲染不一样"的原因。

**字体**：中文换成**阿里巴巴普惠体 3.0**，打包 400 / 500 / 600 三个权重的 woff2 分片（约 15 MB）；字体栈把 Segoe UI 放在前面，拉丁与数字用系统 UI 字体，中文回落到普惠体——混排时西文更利落，中文不再是微软雅黑的默认观感。授权与来源见 `src/renderer/assets/fonts/LICENSE.md`。

**工作区内部**：

- 侧栏：模式胶囊（灰底容器里白块选中）+ 文档入口；下面是整宽的「⊕ 新会话」按钮（白底、1px 细边、10px 圆角、36px 高、内容居中），再往下三行导航（搜索 / 文档 / 记忆）；`工作区` 分组下的排版是**一棵树**：一行「📁 工作区名」，下面挂这个工作区的会话，`会话标题与工作区名左对齐`（31px），卡片铺满整行、行尾是相对时间与失败标记，hover 才出 `···`（重命名 / 删除，删除二次确认）；**没有「最近对话」分组**，没有会话时整块只留一行居中的「暂无任务数据 :)」。分组标题右侧的 `+` 收进 hover，静态时看不见，不跟截图里的干净排版打架。
- 列宽：左侧栏固定 232，中间对话区 `flex: 1`，右侧文档区可拖拽（280–760，窗口小的时候按 `innerWidth - 560` 收口），分隔条 7px 宽、悬停/拖动才出现 2px 竖线，双击回到 372，聚焦后方向键 ±24；宽度写进 `localStorage`，关掉文档区时分隔条一起消失。
- 文档渲染按类型分流（`FilePreview.tsx`）：`.md` 走 `react-markdown` + `remark-gfm`，标题/列表/引用/表格/链接排成文档，围栏块复用代码面板、外链交给系统浏览器；其余文本按扩展名选 Prism 语法，逐行拆成「行号 + 高亮 HTML」（跨行 token 会在换行处闭合再重开，保证每行标签平衡）；图片通过 `fs/read-image` 取 data URL 内联显示（≤8 MB）；未知类型仍是纯文本。diff 视图保持逐行 +/− 的原样。
- 代码面板（`CodeBlock.tsx`）只有一块，文档源码、`.md` 围栏和助手回复的围栏都复用它。头部一行是语言（文件扩展名或围栏标签）、行数和常显的复制按钮；行号是独立的 grid 列，软换行的续行落在代码列而不是跑回行号下面，跨行选择也不会把数字带进剪贴板。字号 12px、行高 1.7、`tab-size: 2`，等宽栈按 SF Mono → JetBrains Mono → Fira Code → Cascadia → Consolas 回落，中文注释落到普惠体而不是宋体；注释不用斜体（中文没有真斜体，合成的倾斜像渲染坏了）。token 色按「关键字 / 字符串 / 数字 / 类型 / 标签 / 注释」六个角色分配，暖纸上都过 4.5:1，深色另配一套。diff 与源码共用行号列宽和符号列。
- 思考模型的回合：助手文字与工具调用是两条 item，回放时会变成两条连续的 assistant 消息。DeepSeek 的思考模式要求本轮每条 assistant 消息都带 `reasoning_content`（模型没产出时也必须是空串），否则第二步就 400。所以 `MessageItem` / `ToolCallItem` 都存完整 reasoning，`toMessages(..., thinking)` 在 `ContextState.thinking` 为真时给所有 assistant 消息补该字段；`complete()` 再兜一层：遇到这类 400 就给缺失字段补空串重发一次。`ContextState.thinking` 一旦在本会话里见过 reasoning 就置真，普通模型不会收到这个额外字段。
- 编辑模型走和添加同一套面板：`select-static` 展示锁定的供应商/类型/模型（模型名由 `modelTitle()` 还原品牌大小写），只留 API Key 输入（占位「留空以沿用当前 API Key」）和「校验并保存」；校验先调 `onTest`，失败给「仍然保存」。显示名与接口地址不再可改，避免改坏已保存的 profile。
- 设置里的模型是「一张卡片 + 多行」：`effectiveProvider()` 决定徽标颜色和副标题（老配置没有厂商 id 时按接口地址匹配目录），`modelTitle()` 把 `deepseek-v4-pro` 渲染成 `DeepSeek-V4-Pro`；每行右侧是 `···`（设为当前/编辑/删除）和开关。开关写 `enabled`，关掉的模型从选择器里过滤，若关的是当前模型则自动切到下一个可用的。
- 模型选择器按厂商分组：`ModelProfile.provider` 记录添加时选的厂商 id，菜单用 `providerByName` 分组；老配置没有该字段时按 baseUrl 前缀匹配目录，自定义端点退回主机名（`api.mimo.example` → Mimo）。组内按模型 id 排序，顶部搜索框同时过滤模型名、显示名和厂商名。
- 品牌标（`BrandMark.tsx`）是产品本身的一部分：一块高级黑的圆角方片，上面两只奶白色的眼睛——左边 `|`、右边 `<`（粗圆头笔画）。状态机是 `idle → happy（悬停）→ surprised（按下）`，动效只动笔画：左眼变宽、右眼轻推、整体收紧/上浮，闲置时按 3.6–6.2 秒让左眼闪一下；`data-expression` 暴露给测试和样式。图标由同一份几何重绘进 `build/icons/*` 与 `build/icon.ico`（`npm run icons`），窗口、任务栏、安装包和标题栏是同一个标记。
- 批准方式的三档是用户的选择，不是错误状态：都用 `.tb-chip` 的中性色，只用图标区分（盾勾/盾/开锁），「完全访问」不再套 danger 红。
- 工作区会话作用域：侧栏按 `thread.cwd === 当前工作区` 过滤，切换工作区不会把旧会话显示在新目录下。
- 对话列水平内边距 32px，等于悬浮输入框的 16px 外边距 + 16px 圆角，文字与圆角结束端点对齐。
- 对话滚动视口的下边界取输入框 `.composer` 的下边界（App 里量 `--dock-gap`），底部的元信息行留在滚动区外。
- token 台账存在 `index.json` 的 `tokenDays`（按本地日期累加），`activity/get` 读出每天的 tokens；热力图按 token 分级，悬浮用玻璃提示框。
- 默认设置不再预置模型，默认工作区为空字符串；DEMO 模式单独注入一个展示用 profile。
- 停止按钮会中止模型请求并 `taskkill` 整棵命令进程树；回合收尾时把未返回结果的工具补成「已中断」结果，重启恢复同样处理。
- 窗口用 `frame: false`：原生标题栏在系统里可能被强调色染成别的颜色，改成自绘的 52px 标题条 + 最小化/最大化/关闭按钮（`xiaohey:window` IPC），按钮颜色走 `--ink-2/--hover/--danger`。
- 主题色来自应用图标：墨黑 + 奶油。浅色用暖纸底（#f7f3ec）与面板 #fffdf9，主操作墨黑 #1f1c17 配奶油字 #f7efdf，选中行奶油 #efe7d7；深色反转（面板 #1b1815，主操作奶油 #e8dcc4 配墨黑字）。语义色只用于增删（#2f7a4f / #b8453a）与警告（琥珀），不进入底色。
- 「新会话」建的是无工作区会话（`thread.cwd = ""`）：发送会先被 App 拦下并提示「请选择工作区」，草稿保留；选择目录后走 `thread/set-workspace` 绑定到该会话，而不是新开一个。
- 工作区选择器是挂在 `body` 上的 fixed 弹层（`createPortal`），坐标取触发按钮的 rect：放在滚动容器里会被 rail 的 `overflow` 裁切并把 rail 横向滚动 31px（图标被推出可视区）。面板内容顺序按参考图：搜索 → 本机 → 工作区列表（当前打勾）→ 分隔线 → 新建工作区 / 连接 SSH 主机（占位）。
- 工作区不再固定：点侧栏的工作区行弹出 `workspace-menu`，「打开或新建工作区…」调 `workspace/pick`（系统目录选择框，允许在框里新建文件夹），选中后 `thread/create` 带 `workspace` 建一个该目录下的会话；`thread/create` 校验路径必须是绝对路径且是目录。最近工作区存 `settings.recentWorkspaces`，菜单里可直接切回。
- 工作区侧栏是可拖动的：`.rail-splitter` 与文档区分隔条同一套交互（拖动、方向键、双击复位），宽度存 localStorage（`xiaohey-rail-width`，200–420），列表容器 `overflow-x: hidden` 且行用 border-box，避免出现横向滚动条。
- 侧栏只保留可操作的信息：会话行是标题 + 运行/失败状态，不放相对时间（时间噪音大且不帮助选择）；工作区行用普通文件夹图标，不带 git 角标。
- 对话导航是 `TurnMinimap`：一条 turn 一条 `minimap-stripe`，等间距堆叠并整体垂直居中（默认 9px，超出高度时压到最小 3px），不做按内容比例铺开；`.transcript` 用 `scrollbar-width: none` 与 `::-webkit-scrollbar { display:none }` 隐藏原生滚动条；常态是 10×1.5px 的细线，**正在读的那一轮最长（20px）**并随滚动实时更新（取视口上 1/3 处所在的那一轮，贴底时取最后一轮，这样长线始终对应「现在看到的区域」）；悬停只是次长（16px，不会盖过当前阅读的那条），tooltip 是一张卡片：bold 标题为该轮 user 文本，正文是这轮最后一条助手回复的前三行；click 用 scrollTo 平滑跳到那一轮。
- 助手回复走 `MarkdownText`（react-markdown + remark-gfm）：行内代码、列表、围栏块、表格、链接都能渲染，外链交给系统浏览器；用户消息保持纯文本，避免把自己写的反引号也格式化。
- 对话区占满面板（`.timeline` 宽度 100%，只保留 transcript 的 24px 内边距），助手回复不设行宽上限、左对齐铺满；用户消息右对齐成气泡（最大 78%），只有它不占满——这样一眼能分出「谁在说」，也保持回复的阅读宽度。输入框与对话区同宽同起点。
- 过程默认折叠：`open` 初始为 false；`live` 变 false 时再折一次，避免用户在运行中展开后一直留着。
- 回合是对话的展示单位（`TurnBlock`）：用户消息 → 状态行 → 过程层 → 最终答案。过程层把 reasoning、tool call、notice、plan、checkpoint、approval、compaction 按时间顺序排成行；工具行是中文动作 + 参数 + 耗时，点开才有输出。`live` 为真时状态行只有一行：「正在执行 · 当前动作 · N 秒」（当前动作取最后一个未完成的工具调用，没有就写「思考中…」），状态行本身带转圈，会话头的运行状态也带转圈；展开后的过程行、工具行同样保留转圈。结束后折成「已完成 · 用时 X」并保留答案；折叠态多一行 `summarizeTools()` 生成的操作摘要（已读取文件、搜索代码、写入文件等），摘要只是一行说明，不承担点击；展开只由状态行负责，避免同一件事出现两个开关。错误/警告类 notice 不放进折叠层，始终显示在状态行下面，失败不会被藏起来。结案时间取该轮首尾 item 的间隔，不依赖未持久化的 turn 记录。
- 输入框的上下文：`+` 是菜单（引用文件 / 打开文件面板），不是单一动作。引用用 `@path` 表示，文档区文件行可拖进输入框；`MessageItem.references` 存文件名与内容，`toMessages` 把它拼成 `<referenced-files>` 块，气泡仍然只显示原始文字——用户看到的是自己写的话，模型看到的是文件内容。
- 会话级操作放在 `···` 里：重命名、复制为 Markdown、导出到 `exports/`、删除（二次确认）。复制与导出共用 `renderMarkdown(doc)`，保证两边内容一致。
- 审批是「可查 + 可永久放行」：文档区新增「审批」页签列出每条命令与决定；审批卡的「总是允许这条命令」写入 `settings.allowedCommands`，`approve()` 先查内存会话表再查设置表。
- 问题澄清是一个工具（`ask_user`），不是一句普通追问：模型遇到会改变结果的分歧时调用它，本轮停在输入框上方磁吸的一张提问卡上（2–4 个选项，每个可带说明，外加自定义输入）；用户的选择写回 tool result，**同一轮继续**，不另开一轮。回答/取消后卡片落回时间线对应位置，历史可见。`QuestionItem` 单独持久化（问题、选项、回答），重启后仍能看到问过什么、选了什么；没答完就退出/停止的会标成已取消。提问期间 `runtime.phase = 'question'`（状态行显示「等待回答」），停止键仍然可用。
- 任务清单是输入框上方的磁吸卡（`TaskList`，在 `composer-dock` 里）：只在本轮 `running`、且本轮 `todo_write` 给出 ≥2 个未丢弃步骤时出现；标题带「N 已完成 · N 进行中 · N 待处理」，行内是勾 / 转圈 / 空心圈三态，可折叠；本轮结束自动消失，历史计划仍留在过程折叠层的 `PlanCard`。`plan` 状态在 `item/upsert` 收到 `plan` 条目时同步，文档区概览也实时刷新；磁吸卡出现导致 dock 变高时，转动期间的滚动会跟到底部，最后一行不会被任务卡挡住。
- 输入框上方的磁吸卡（排队、任务、提问）左右各内缩 16px：左边缘对齐左上角圆弧结束后的直段起点，右边缘对齐右上角圆弧终点；审批卡同样内缩 16px。
- 快捷键走一个 window 级监听：`Ctrl/Cmd+N`、`,`、`B`、`Shift+B`，`Esc` 中止回合；输入框里的 `Enter` 仍然只负责发送。
- 长对话里向上滚会离开底部，出现「回到最新」；滚动距离用 240px 阈值，回到底部后按钮消失。
- 完成通知只在 `document.visibilityState === 'hidden'` 时发，避免盯着窗口时被打扰；点击通知会恢复并聚焦窗口。
- 单实例：`requestSingleInstanceLock()`，第二次启动把主窗口叫到前台后自己退出。
- 契约护栏只作用于会改动的工具（`mutating`）：读操作永远放行；禁止项只保留标记词之后的子句，避免「修复 lib/stats.mjs，不要改测试」把 `lib/stats.mjs` 也判成禁改路径。
- 空会话首屏：一张贡献图式的**使用频率热力图**，左上角只写「会话」，没有标题副文、没有图例、没有星期列；月份标签放在网格下方，52 列铺满卡片宽度（CSS grid 等分列 + 正方形格子）。数据由 `activity/get` 对全部会话的 items 按本地日期聚合；演示模式下另注入一份确定性的历史，避免首启截图是一张空网格。整组（品牌行 + 热力图 + 输入提示）在会话区**垂直居中**，下面是输入提示，不再堆说明文字。
- 用户菜单：没有账号体系，所以「退出登录」要二次确认，语义是清掉唯一一份凭据（`settings.json` 里的 API Key），会话、检查点、记忆不动；清完弹一条顶部 toast，重新填 Key 即可继续。设置页仍然只有模型，入口就这一个。
- 品牌标：标题栏左边是一块高级黑的圆角方片（`BrandMark.tsx` 里的一段 SVG，18px），上面奶白色的 `| <` 眼睛，空状态放大到 26px 复用；标题栏只留「标 + xiaohey」，不再重复显示工作区名。应用图标 `build/icon.ico` 用同一块方片和同一双眼睛；`build/icons/*.png` 同步生成。
- 会话头：标题、`···`（重命名是原地输入框、删除要二次确认）、运行状态；右侧只留文档区开关。工具数量这类内部信息不占界面。
- 会话流：没有发言人标签，用户消息是一块 `#f7f7f7` 圆角块，助手就是正文；工具调用是 1px 描边卡片，展开后输出落在更浅的内嵌面板。
- 改动卡片：图标块 +「已编辑 N 个文件」+ 总 `+a −d`，右侧 `撤销`、`审查`，卡片内逐文件 `+a −d`，超过三个折成「再显示 N 个文件」。数字由快照捕获时逐文件算行差得到（`checkpoint.ts` 的 `countLineDiff`）。
- 输入框：圆角 16、1px `#e6e6e6` 描边加一层很浅的投影，**比正文列更宽**（正文列 764，输入框最多 900），说话的地方比读的地方宽一点，不挤在文字里；工具条左侧是圆形「+」（打开文件面板）与「修改前询问」下拉，右侧模型切换与鼠尾草绿发送键，运行中发送键就地变成中止方块；**输入框下侧**一行 11.5px 的元信息：`轮次 / 步数`、累计 `tok`、上下文占用环与百分比，右端是工作区名与 git 分支。没有分隔线，也没有独立状态栏——数据贴着输入框，读的时候不用跳视。
- 模型清单：`Settings.models` 是一个数组，`activeModelId` 指向当前使用的那个。切换模型只写 `activeModelId`，不碰任何字段。新增走**供应商向导**（对齐 Qoder 的添加模型对话框）：供应商（推荐 DeepSeek / 阿里云百炼，更多 智谱 / Kimi / MiniMax，自定义 OpenAI Compatible，各带品牌色徽标）→ 类型（Token plan / 按量付费，右侧「购买 Token Plan ↗」外链）→ 模型 → API Key（右侧「获取 API Key ↗」外链，密码框内置眼睛按钮）。**模型列表来自供应商的 `GET /models`**（`src/main/runtime/models.ts`，12 秒超时，去重排序），所以永远是这把 Key 真能调的模型；超过 8 个给筛选框，支持全选、多选；拉取失败给出具体原因（401/连不上/超时）并允许手填模型名兜底。底部只有一个「校验并添加模型」：先发一次真实请求校验，通过才写入，失败显示原因并给「仍然添加」；标题栏右侧有收起 / 关闭。选几个就一次写入几条 profile；编辑才展开接口地址、上下文窗口、输出上限、温度。设置是独立页面（左侧导航：模型 / 外观 / 使用统计 / 关于，顶部「返回应用」）。旧版单个 `model` 字段在 `normalizeSettings()` 里升级成清单第一项；清单被删空时 `activeModelId` 变成空串，输入框仍可打字，发送被禁用并提示先添加模型。
- 元信息右端：工作区名 + 当前 git 分支。分支由服务端 `workspace/info` 用 `git symbolic-ref --short HEAD` 取（没提交的空仓库也能答），失败再退到 `rev-parse --abbrev-ref`，不是仓库就返回 `null`，界面只省掉分支那一项。启动、每轮结束、刷新侧栏时各取一次，切分支不用重启。
- 数据来源：轮次是 `thread.turnCount`，步数是 `thread.steps`（每次模型调用 +1，跨轮累计），累计 token 是 `thread.totalTokens`（每次模型调用的 prompt+completion 累加），百分比是 `gauge.tokensUsed / contextWindow`。
