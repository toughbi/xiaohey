## 测试中发现并已修复的缺陷

1. **新建会话偶发出现两行（高危）**
   现象：点一次「新会话」，侧栏出现两条同名会话，两条都显示为选中，行菜单会同时展开两个。
   原因：`thread/create` 返回前服务端已经广播 `thread/list`，客户端随后又把自己创建的会话前插一次。
   修复：前插前按 id 去重（`App.tsx`），并以服务端列表为准。
   验证：S3（1 行）、V4（双击 → 2 行 1 个唯一标题）。

2. **运行中「停止」不生效（高危）**
   现象：模型请求挂住时点停止，按钮仍是停止状态，回合继续跑约 3 秒才结束。
   原因：请求被 abort 后 `complete()` 仍按可重试错误走退避重试（400/800/1600ms），并且新请求带着已 abort 的 signal 又失败一次。
   修复：`llm.ts` 中 `signal.aborted` / `AbortError` 直接中断，不进入重试。
   验证：W3（挂起请求 → 停止 → 1.2s 内回到空闲并给出「本轮已中止」）。

3. **改动卡片的「撤销」是空操作（高危）**
   现象：写入文件后卡片显示 `已编辑 1 个文件 +0 −0`，点「撤销」提示「已还原 1 个文件、删除 0 个」，但文件仍在、内容没变。
   原因：快照是在工具执行**之后**捕获的，回退只是把当前状态再写一遍；对比基线也是自己，所以 diff 全是 0。
   修复：`executeTool` 改为**执行前**捕获快照，执行后用新增的 `Checkpoints.restat()` 以快照树为 before 重算 diff；卡片指向执行前的快照。
   验证：G5（`+1 −0`）、G6（撤销后文件从磁盘消失）、U4（demo 回退后磁盘内容确实变了）。

4. **配置文件损坏后每次启动都重新解析垃圾（中危）**
   现象：`settings.json` 写入非法 JSON 后应用能启动（内存里回落默认模型），但文件一直不被修复。
   修复：`Store.init` 在归一化结果与磁盘内容不一致时写回（同时覆盖旧版单模型结构）。
   验证：V1（损坏 → 启动 → 文件被重写为合法结构）、V2（旧版 `model` → 模型清单 + 保留 `approval`）。

5. **「测试连接」只显示 `fetch failed`（体验缺陷）**
   修复：把网络类错误翻译成「连不上 <baseUrl> —— 检查地址是否正确、本机服务或代理是否已启动」。
   验证：T5。

6. **首屏输入框点不动（高危）**
   现象：全新安装、还没有任何会话时，输入框是 `disabled`，点不进去，但空状态写着「输入第一句话开始」。
   原因：`Composer` 的 `disabled` 直接绑了 `!activeId`，把「没有会话」和「不能输入」混成一件事。
   修复：输入框永远可输入；发送改由 `blocked`（没有可用模型）控制，并在无模型时把占位文案换成「先在设置里添加一个模型」。`App.send` 在没有活动会话时先建会话再发第一句。
   验证：X1（首屏可点击可输入）、X2（首句自动建会话并收到回复）、X3（空内容仍不能发送）、X4（无模型时可输入、发送禁用并给出提示）。

7. **模型列表是写死的（功能缺失）**
   现象：添加模型时列出的是内置的固定 model id，和这把 Key 实际能调用的模型无关，供应商上新模型也只能等应用更新。
   修复：新增 `provider/models` 请求与 `src/main/runtime/models.ts`，用 Key 请求供应商的 `GET /models`（12s 超时、去重排序）；界面拆成加载/成功/失败三态，失败显示 401、连不上、超时等具体原因，并提供「手动填模型名」兜底；超过 8 个模型给筛选框。
   验证：Y1（列表来自 `/models`）、Y2（全选一次写入多条）、Y3（筛选）、Y4（401 → 显示原因 → 手填仍可添加）、单元测试覆盖 401/去重/地址格式。

## 缺失的交互与功能（按优先级）

### 高

1. **输入框无法真正“带上下文”**：`+` 只打开文件面板，不能把文件/目录引用进这条消息，也没有图片、拖拽、粘贴附件。用户想让模型看某个文件，只能靠它自己 `read_file`。
2. **消息与工具输出无法复制**：回答、命令、diff 都没有复制按钮，代码块也没有一键复制，长输出只能选中拖拽。
3. **会话没有“复制/导出”**：无法把一次对话导出为 Markdown，也没有“复制全部”。
4. **失败回合没有重试入口**：只能重新输入一遍；错误通知里也不带“重试”按钮。
5. **审批历史不可查**：批准记录散落在时间线里，没有集中列表，也没有“永久允许这个命令”的粒度（目前只有本会话允许）。

### 中

6. **没有键盘快捷键**：只有 Enter/Shift+Enter；新建会话、打开设置、切换侧栏/文档、停止回合都没有快捷键，也没有快捷键说明页。
7. **没有“回到最新”按钮**：滚动离开底部后不会出现新消息提示或跳回按钮（自动吸底只在接近底部时生效）。
8. **设置搜索只过滤左侧导航**，不搜索页面内容；类型下拉只有一个「按量付费」，是个点开没有其它选项的死控件。
9. **文档区**：没有刷新、文件搜索、“在资源管理器中打开”、上传；面包屑只能回根目录。
10. **记忆只能删不能加/改**：用户不能手动记一条事实，也不能编辑现有事实。
11. **检查点回退没有预览**：点一下就回退，看不到将要恢复哪些文件；回退本身也不能再撤销。
12. **会话列表**：不能置顶/收藏、不能复制、不能按时间或状态排序；失败会话没有醒目标记之外的入口。
13. **没有完成通知**：窗口失焦时回合结束没有系统通知或任务栏提示。

### 低

14. 供应商图标是首字母方块，不是品牌标识；供应商列表缺「小米 MIMO」（没有公开的 OpenAI 兼容端点，未编造）。
15. 无首次使用引导：全新安装时输入框是禁用的，用户需要自己找到左下角齿轮去配模型。
16. 无 `aria-live`：新消息与状态变化对读屏软件不可见。
17. 无多窗口/多实例防护：同一 `XIAOHEY_HOME` 被两个实例打开时只有租约层面的保护。

### 联调发现并修复的缺陷

8. **思考型模型的多步回合全部失败（高危）**
   现象：`deepseek-flash` 第一步工具调用成功，第二步请求就 400：`The reasoning_content in the thinking mode must be passed back to the API`。8 个场景里 5 个直接卡死。
   根因：我们把「助手文字」和「工具调用」存成两条独立 item，回放时生成两条连续的 assistant 消息，而 DeepSeek 要求本轮每条 assistant 消息都带 `reasoning_content`；另外部分步骤模型没有产出 reasoning，我们直接省略了该字段。
   修复：`MessageItem`/`ToolCallItem` 记录完整 reasoning；`toMessages(..., thinking)` 在思考模式下给**所有** assistant 消息补 `reasoning_content`（无内容时补空串）；`complete()` 增加一次自愈重试——遇到这类 400 就给缺失字段补空串再发一次，覆盖模型没产出 reasoning 的步骤。新增单元测试覆盖两种模式。
   验证：C1/C2/C3 由失败转为通过，全量 8/8。

9. **契约护栏误伤正常读写（中危）**
   现象：任务里写「不要修改 test/ 下的测试文件」时，`lib/stats.mjs` 的写入也被判为越界；只读任务里读 `src/render.mjs` 也被拦。
   根因：`buildContract` 把包含禁止词的整句当成禁止项，`checkDrift` 再从整句里提取路径，于是「修复 lib/stats.mjs，不要修改测试」里的 `lib/stats.mjs` 也成了禁改路径；护栏还对所有工具生效（包括只读）。
   修复：禁止项只保留标记词之后的子句；护栏只作用于会改动的工具（`mutating`），读操作不再被挡。
   验证：C2、C4 稳定通过；`npm test` 30/30。

### 仍然没做

- **供应商品牌图标**：「小米 MIMO」缺公开的 OpenAI 兼容端点，没有编造；其余供应商仍是品牌色首字母方块，不是官方 logo。

**21/21 通过。** 期间发现并修复：

1. **表格在窄窗口溢出**：给 Markdown `table` 包一层 `.md-table-wrap`（`overflow-x: auto`），单元格加 `overflow-wrap: anywhere`；超长 token 换行而不是撑破列。
2. **minimap 卡片显示原始 Markdown**：摘要里会出现反引号、`**`；改成先剥掉标记再进 tooltip。
3. **minimap 卡片被裁切**：`.minimap` 的 `overflow: hidden` 把左侧卡片裁掉了，已移除。
4. **minimap 条纹过散**：改为等间距、垂直居中、常态 10×1.5px 的细线。

新增离线用例 Pass 26（5 项）：宽表格滚动/不溢出、240 字符 token 换行、长代码行内部滚动、tooltip 纯文本。

尚未覆盖：真实供应商的 SSE 边界（空 delta、非标准 tool_calls 增量）、多显示器缩放、输入法组合态、系统级拖拽。

## 未覆盖 / 残余风险

- 只用一个本地假端点验证协议；不同真实供应商的 SSE 差异（`reasoning_content`、空 delta、非标准 `tool_calls` 增量、超长响应）没有逐个跑过。DeepSeek flash 是唯一跑过的真实模型。
- 没有做真实的大仓库（数万文件）性能测试；每次变更都会复制整棵工作区树（跳过 `node_modules`/`.git`/`dist`），大仓库下会明显变慢。
- Windows 原生标题栏按钮（最小化/最大化/关闭）由 Electron 提供，未纳入自动化断言。
- 中文输入法组合态、拖拽选文件、多显示器缩放等操作系统级交互未覆盖。
